<p>打开网页的时候如果出了问题，浏览器上会出现一行小字：404 Not Found，或者 403 Forbidden。这几个三位数字叫 HTTP 状态码，是服务器给浏览器的回话。它要回答的其实只有一件事：你要的东西，我给没给。给了是哪种给法，没给又是为什么。</p>
<h2>三个数字，第一位最重要</h2>
<p>所有状态码都是三位数，第一位表示大类，后两位只是编号。这个规则不是网络时代发明的，是从更早的 FTP 和 SMTP 沿用下来的，1996 年写进 HTTP/1.0 的标准（RFC 1945）之后一直用到现在。</p>
<p>第一位的五种含义分别是：1 字头表示请求收到了、还在处理；2 字头表示成功；3 字头表示东西不在这里、要去别处拿；4 字头表示问题出在客户端；5 字头表示问题出在服务端。</p>
<p>对普通用户来说，真正要分清的只有 4 和 5。4 开头意味着你可能要改点什么，比如换个地址、换个账号、少传点东西；5 开头意味着你什么也做不了，只能等对方修。</p>
<h2>1 字头：基本见不到</h2>
<p>这类码是中间状态，浏览器收到后自己处理掉了，不会显示给你看。</p>
<p>100 Continue 用在客户端先问一句「我要发一个大文件，你收不收」，服务器回 100 表示可以发。103 Early Hints 是 2017 年新增的，服务器在准备页面的同时先告诉浏览器「等下要用这几个文件，你可以先开始下载」，用来加快首屏显示。</p>
<h2>2 字头：成功，但方式不同</h2>
<p>200 OK 最常见，请求成功，内容就在响应里。</p>
<p>201 Created 表示成功并且新建了一个资源，通常出现在提交表单或调用接口新建数据之后。</p>
<p>204 No Content 表示成功，但没有内容可回。删除一条数据、保存一个设置，服务器常常回这个。它和「卡住了」不一样，204 是明确的「做完了，没什么可说的」。</p>
<p>206 Partial Content 用在断点续传和视频拖进度条上。客户端说「我只要从第 1000 字节开始的那一段」，服务器就只发那一段。</p>
<h2>3 字头：换个地址</h2>
<p>这类码的意思是「东西不在这儿」，但换的方式有区别。</p>
<p>301 是永久搬家，浏览器和搜索引擎会记住新地址，下次直接去新地方。302 是临时搬家，这次去新地址，下次还来老地址问。</p>
<p>307 和 308 分别对应 302 和 301，差别在于请求方法保不保留。早期的 301 和 302 允许浏览器把 POST 改成 GET 再跳转，这个历史行为带来过不少麻烦。307 和 308 明确规定跳转后方法不变，原来是 POST，跳过去还是 POST。所以搬一个接收表单的接口，应该用 308。</p>
<p>304 Not Modified 是缓存用的。浏览器问「这个文件变了没有」，服务器说「没变，你手上那份还能用」。这时不传内容，省流量。</p>
<h2>4 字头：客户端的问题</h2>
<p>这一类数量最多，也最容易被误读。</p>
<p>400 Bad Request 最笼统：请求格式不对，服务器看不懂。</p>
<p>401 和 403 经常被搞混。401 的名字叫 Unauthorized，直译是「未授权」，但它真正的意思是「没有经过身份验证」——名字起错了，这是历史遗留。区别在于：401 是「我不知道你是谁」，403 是「我知道你是谁，但你不能看这个」。密码输错了是 401，登录之后去点管理员页面是 403。</p>
<p>404 Not Found 最有名：服务器上找不到这个地址。</p>
<p>值得注意的是，很多网站明明知道你为什么进不去，却故意回 404。因为 403 等于承认「这个文件存在，只是不给你看」，而 404 什么都不承认。</p>
<p>405 Method Not Allowed 表示地址是对的，方法不对。比如一个只能查询的接口，你发了删除请求。</p>
<p>408 Request Timeout 表示服务器等你把请求发完，等太久了。</p>
<p>410 Gone 表示这东西曾经存在，现在永久删除了，也没有新地址。它和 404 的差别是：404 是「我不知道有没有」，410 是「确定没了」。</p>
<p>413 和 414 是一对，都是「你给的东西太多」，一个管内容，一个管地址。413 是上传的文件超过了服务器允许的大小。414 是网址太长。</p>
<p>414 在日常浏览里很少见，通常出在两种情况下：一是把很长的查询条件直接拼进了网址，二是重定向配错了形成循环，每跳一次就往网址后面再接一段参数，越滚越长，直到服务器拒绝。</p>
<p>429 Too Many Requests 表示请求太频繁被限流了。它是 4 字头里唯一通常带 Retry-After 响应头的，告诉你多久之后可以再试。</p>
<p>451 Unavailable For Legal Reasons 表示因为法律原因不能提供，法院命令、版权投诉、地区屏蔽都回这个。编号是故意的，取自雷·布拉德伯里的《华氏451》——451 华氏度是纸张自燃的温度，那本小说写的是烧书。</p>
<p>418 也可以提一句。它来自 1998 年 4 月 1 日 IETF 发布的一份玩笑文件 RFC 2324《超文本咖啡壶控制协议》，规定用茶壶煮咖啡应该返回 418。本来是个愚人节玩笑，后来被写进了不少真实代码。</p>
<p>2017 年标准组织想删掉它，遭到开发者反对，最后在 2022 年的 RFC 9110 里被正式登记为「保留但未使用」，意思是这个号码以后也不能派正经用场了。</p>
<h2>5 字头：服务端的问题</h2>
<p>500 Internal Server Error 最笼统：服务器内部出错，代码抛出了没有处理的异常。</p>
<p>502 Bad Gateway 表示中间的网关向上游服务器发了请求，但上游回的内容不合规矩。</p>
<p>503 Service Unavailable 表示服务器暂时没法处理，通常是过载或者维护。这个也常带 Retry-After。</p>
<p>504 Gateway Timeout 表示网关问了上游，上游在规定时间内没有回话。</p>
<p>这四个码指向的位置不一样：500 在应用代码里，502 在上游返回的内容里，503 在这台机器本身，504 在等待超时上。查日志的时候，这四个数字直接对应不同的排查方向。</p>
<h2>标准之外还有一批</h2>
<p>除了正式登记的号码，日志里还会见到一些 IANA 不认的码，它们是各家服务器自己定的。</p>
<p>nginx 有 444，意思是直接关闭连接、连响应头都不发，用来对付恶意请求。还有 499，表示客户端在服务器回应之前自己断开了，通常是用户等不及关了页面。</p>
<p>Cloudflare 有一组 520 到 526，用来区分不同类型的源站故障，比如 522 是连接源站超时，524 是源站响应超时。</p>
<p>这些码不在标准里，但用得太广，已经成了事实上的方言。</p>
