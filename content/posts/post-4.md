<p>这个站有浅色和深色，还有两套皮肤。听起来像模像样，其实我一开始差点被自己坑死。</p>
<p>最开始颜色是直接写死的。背景一个色号，字一个色号，线一个色号，一个一个敲上去。写了两百多行，页面出来了，看着还行。</p>
<p>写死的时候我一点没觉得有问题。因为每次都是「要用到哪里就写一个」，很自然，也不用想别的。我甚至还为这件事得意过——我不依赖什么框架，纯手写，看着多干净。</p>
<p>然后我加了个深色模式。</p>
<p>那时候我以为这件事就是把颜色换一套。脑子里想得很简单：白底改黑底，黑字改白字，灰线改深灰，半小时的事。</p>
<p>那天下午两点改到六点。不是改不出来，是改不完。颜色散在几百个地方，改到一半忘了哪些改过，只能从头用搜索一个个找。找到后面眼睛都花，还是漏了两块，深色模式下那几块白得特别刺眼。</p>
<p>漏掉的那两块最难受。因为切换之后整个页面已经暗下来了，那两块白得特别显眼，像两张贴上去的纸。我当时甚至怀疑是不是浏览器缓存，刷新了好几次才承认是自己漏了。</p>
<h2>后来才知道有变量这回事</h2>
<p>更气人的是，变量这件事我不是没听过。我上学的时候就学过，也知道 CSS 里可以定义变量。我只是没想到要用在这儿。</p>
<p>就是给颜色起个名字，放在最上面，后面用的时候写名字：</p>
<pre><code>:root {
  --bg: #fbfaf8;
  --ink: #16161a;
  --line: #e6e3dd;
}

body {
  background: var(--bg);
  color: var(--ink);
}</code></pre>
<p>要换颜色，改上面那三行就够了，别的地方一个字都不用动。</p>
<p>看起来只是把颜色挪了个位置，但它其实改变了「谁说了算」这件事。以前颜色散在各个地方，每个地方都是自己说了算；现在颜色由最上面一份清单说了算，下面的人只是引用。这个结构一旦立起来，全局的变更才有可能。</p>
<h2>深色模式花了十分钟</h2>
<p>因为所有地方用的都是 var(--bg) 这种写法，只要重新给一遍值：</p>
<pre><code>[data-theme=“dark”] {
  --bg: #101114;
  --ink: #ededed;
  --line: #272a30;
}</code></pre>
<p>js 那边只改一个属性：</p>
<pre><code>document.documentElement.dataset.theme = “dark”;</code></pre>
<p>就这么一行。改完我坐那儿愣了一下，觉得前面那个下午白干了。</p>
<p>那种感觉挺具体的：不是学到了新东西的兴奋，是「我居然用了这么久才想到」的懊恼。而且我脑子里立刻闪过下午那几个小时里干的事——搜索、替换、再搜索、再看漏没漏。这些动作一点都不难，纯粹是重复劳动。重复劳动最消耗人的地方是它不产生任何积累，做完之后除了累，什么都没有。</p>
<h2>踩过的几个</h2>
<p>一个是变量里存的必须是完整的一段。我试过存一个 8px 进去，然后想再拼一个 4px，不生效。它不是一个数字，是一整段值，拼不了，得拆成两个变量。</p>
<p>当时我以为它会像字符串那样接起来，还试了好几种写法。后来才想明白：在拼之前，浏览器已经把 var() 替换成它存的那段文本了，所以不能拿它去做算术。要算，得先去算，再存进去，或者直接用 calc() 把运算写在引用那一层。</p>
<p>这个坑其实暴露了我对它的理解很浅。我把它当成「一个变量」，但它更像「一段预先写好的值」。什么时候变成那段值、什么时候还能参与计算，是有顺序的。</p>
<p>还有一个不算变量的事，是我自己打错了一个字母，找了一个多小时，一直在怀疑是浏览器的问题。</p>
<p>那一小时里我刷新了无数遍，换过浏览器，看过控制台里根本没报错，甚至怀疑是我改的那行 js 没生效。最后是盯着那段代码一个字一个字读，才发现变量名少了一个字母。控制台不报错是因为那个属性的名字写错了，但 CSS 里写错名字不会报错，它只会「什么也不做」。</p>
<p>这件事之后我给自己加了个习惯：写 CSS 变量名的时候，先在清单里加上，再从清单里复制过去用。看着慢，实际省时间。</p>
<p>另外记得加一句 color-scheme: light dark。不加的话深色模式下滚动条还是白的，看着像贴了张纸条在上面。</p>
<p>这一条是被很多人忽略的。页面主体全暗下来了，滚动条和输入框还是亮的，那个反差比整页都亮着还刺眼。它不报错，也只是一个小面积的白，但就是能让人一眼看出「这个站没有好好做深色模式」。</p>
<h2>这件事改变的不只是颜色</h2>
<p>做完这件事之后，我把站里别的东西也重新看了一遍。发现类似的「散在各处、其实是同一份信息」的地方还挺多：字号、间距、圆角、阴影，全是我一个个写死的。</p>
<p>于是我把它们一件件收进变量。收的过程没什么技术含量，就是把散的值抄到最上面，再一处一处换掉。但收完之后，改动的速度完全不一样了。以前调整个页面的圆角要花半小时，现在改一行。</p>
<p>我后来理解了一件事：写死本身不是错，错在「不知道它可以变」。一件事如果确定不会变，写死没问题。我是不知道它会变，所以默认它不会变。</p>
<p>现在加皮肤、改主题色，基本就是改几个数。说「给以后的自己留后路」有点夸张了，其实就是不想再花一个下午，去找哪个颜色写错了。</p>
<p>两套皮肤现在就是两组变量。加第三套的时候，我只加了十几行，没用上半小时。这大概是那个下午最有价值的回报。</p>
