# 更新日志

reze520.top 的改动记录。按日期倒序，只写事实：改了什么、为什么改、怎么改的。
站内「时间线」页与本文件保持同一口径。

## 2026.10.27

### 导航页扩容至 157 个站点

- 站点由 58 个扩充到 157 个，按 14 类归档：AI 工具、开发技术、设计素材、效率工具、
  新闻时政、政府服务、社交社区、学术文献、金融财经、数理工具、人文历史、影音娱乐、
  漫画阅读、生活服务。
- 全部站点在无代理的国内网络下逐个探测。判定标准：能建立连接并返回 HTTP 响应即为可用
  （403 / 401 属正常，多数站点对非浏览器请求有限制）。据此移除 10 个无法访问的入口：
  ChatGPT、Gemini、Suno、YouTube、V2EX、Squoosh、Wallhaven、Notion、英为财情、维基百科。
- 探测过程中需要注意的一点：给请求加 `Range` 头会让部分站点（如优酷）返回 503，
  造成误判。连通性检测不应带该请求头。
- 图标改为本地缓存，157 个站点合计 1.5 MB，不依赖任何在线图标服务。
- 分类卡片底色加深一档，避免背景图透出影响正文可读性。

### 音乐播放器：曲目列表与播放模式

- 新增曲目列表，支持切换曲目与上一首 / 下一首。原先的 `±10 秒` 按钮语义改为切歌。
- 播放模式改为顺序循环 / 单曲循环 / 随机三态轮换，选择结果持久化；随机模式排除当前曲目。
- 歌词区改为默认收起，由按钮展开。
- 单曲循环角标返工：原先挂在按钮的 `::after` 上，与 `[data-tip]::after` 的悬浮提示共用
  同一伪元素，`content` 被高优先级规则覆盖，悬停时显示为一个只有「1」的深色方块。
  改为按钮内的独立 `<i>` 元素，由 `[data-mode="one"]` 控制显隐。

### 修复音频进度条无法拖动

- 排查顺序：先验证音频文件本身的索引、码率、时长，均正常；问题不在文件。
- 根因：站点静态资源响应缺少 `Accept-Ranges`，音频请求带 `Range` 时返回 `200` 而非
  `206`，浏览器无法获得分段数据，`currentTime` 写入无效。这一行为对 CSS、图片同样成立。
- 修复：音频资源改由支持分段请求的 CDN 托管（实测返回 `206`），页面主体仍留在原托管。
  CDN 前缀集中定义在 `assets/js/playlist.js` 顶部，更换仓库只需改一处。
- 副作用：CDN 有缓存延迟，新增音频后需等待同步；仓库需保持公开。

### 欢迎页改为常驻页面顶部

- 欢迎页不再隐藏，任意页面向上滚动均可回到。
- 站内切换页面时自动落到内容起始位置，无需先划过大屏。
- 刷新与深链接的落点分别处理：直接打开文章时停在该文章，不影响阅读。
- 落点计算做了幂等处理：路由同步渲染一次、`hashchange` 再触发一次，同一路由只滚动一次。

### 日历并入右栏，移除独立页面

- 删除独立日历页（约 130 行）及全部导航入口，旧链接重定向至首页。
- 右栏日历补充农历、节气与节日，标注发布过文章的日期，支持切换月份与回到当月。
- 不提供日程与记事功能。

### 标签体系与列表分页整理

- 标签由 30 个精简为 7 个：随笔、书评、前端、摘录、情感、英文、影评。
  原标签中 21 个仅使用过一次，筛选后只剩一篇文章，不具分类意义；专名标签全部移除。
- 文章列表每页由 5 篇调整为 12 篇。
- 修复列表筛选函数引用未定义变量 `params0` 导致的运行时报错（此前被外层 try 捕获）。

### 文章与动态文案重写

- 重写七篇文章与四条动态，删除模板化的段落结论、对偶句式与虚构情节，改为具体叙事。
- 文章正文同步至云端存储，文章标识保持不变，旧链接不失效。

## 2026.10.26

### 站点基础

- 无框架、无依赖，手写 HTML / CSS / JS，整站静态。
- 三栏结构：左信息栏 + 中内容 + 右动态；首页、文章、关于统一布局。
- 单页路由：切页只更新内容区，播放器不重建，背景音乐跨页不中断。
- 顶栏导航改版：三段式居中，图标配文字，次级入口收进更多菜单。
- 配色定为淡紫，同步完成暗色模式。
- 全文搜索（Ctrl+K）与欢迎首屏上线。

### 内容与功能

- 在文章之外补齐动态、相册、网址导航三种内容形态；时间线独立记录站点改动。
- 文章页新增目录：从正文标题自动生成，点击跳转并高亮当前章节。
- 接入背景音乐与 LRC 歌词，支持点击展开、随播放进度高亮。
- 播放器改为唱片机样式；歌词支持栏内、悬浮播放器、底部单行三种呈现方式。

### 部署

- Cloudflare Pages 的生产分支为 `Reze520-website`，`main` 不触发构建。
  仓库配置了双推，`git push` 同时更新两个分支。
- 静态资源改动需同步推进 `?v=` 版本号，否则浏览器读取旧缓存。
