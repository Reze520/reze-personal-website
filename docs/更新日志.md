# 更新日志

自己留着看的记录。按时间倒着写，主要记三件事：改了什么、为什么想改、中间卡在哪儿。
隔几个月回来翻，至少能想起当初为什么这么写。

## 2026-10-27

### 导航页从 8 个变成 58 个

原来那页就挂了七八个链接，自己其实也没在用。这次按平时真的会点开的站重新整理了一遍，分成
AI 工具、开发、设计素材、效率、影音、学习资讯、生活实用七类。

图标没走在线接口。那种服务哪天不响应，整页就剩一堆空方块，所以把 58 个站的 favicon 全下下来
塞进 `assets/icons/`，一共才 347KB，比一张照片还小。个别站抓不到就退回显示站名首字。

版式上第一版翻车了：卡片用的是很淡的半透明白，结果背景图直接透上来，文字几乎看不清。把卡片
底色压到 `rgba(21,18,30,.8)` 才正常。以后凡是压在图片上的文字，底色都得够实。

顺手修了顶部「更多」菜单——首页那个下拉里塞了全部七项，跟顶栏完全重复；其他页面只有两项。
现在统一成只放顶栏收起来的那几个，窄屏下相册和导航会自动补进下拉里。

### 播放器：能切歌了

以前只能放两首里的一首，切歌得改代码。现在右上角有个列表按钮，点开是全部曲目，当前那首淡紫
底高亮。上一首、下一首是真的切歌，不再是快进十秒。

歌词以前一进来就摊开一大片，把整张卡片撑得很长。改成默认收着，想看自己点。参考图里是常显的，
但那个位置本来就该留给封面。

播放模式做成一个键轮着转：顺序循环 → 单曲循环 → 随机。选过的会记住。随机挑的时候会排除当前
那首，不然连放两遍同一首歌很怪。

单曲循环那个「1」角标一开始是挂在 `::after` 上的，结果和提示气泡抢同一个位置，鼠标一悬停
就变成一个小黑方块里杵着个 1，看着像 bug。改成独立的 `<i>` 元素才对——顺带记住，`::after`
在一个元素上只有一个，别指望它同时干两件事。

### 进度条拖不动，查了半天不是文件的事

后面几首拖不动，一开始以为是 mp3 少了索引。把所有文件翻了一遍：索引全都有，码率正常，时长也
对，只有第五首带了个 338KB 的异常标签（后来重编码清掉了，但它不是原因）。

真正的原因在服务器：给音频请求加 `Range` 头，回的是 `200 OK`，没有 `Accept-Ranges`，也没有
`Content-Range`。也就是说**整站所有文件都不支持分段请求**。浏览器拿不到分段，就没法跳到中间，
进度条自然拖不动。

前面几首之所以能拖，只是因为它们已经被整个下进缓存了。

解决办法是把音频单独挂到 jsDelivr（仓库本来就在 GitHub 上），那边回 `206`，能拖了。页面还在
原来的地方，只把音频的地址换成 CDN 前缀，写在 `playlist.js` 顶部一行常量里，以后换仓库改一处
就行。

代价是 jsDelivr 有缓存延迟，加新歌得等几分钟；另外它要求仓库是公开的。

### 日历收进右栏

之前单开了一页，顶上还杵着个被放大的图标，看着像心电图，看半天没看出那是"日历"的意思。删了。

右栏本来就有张小日历，只有数字。这次补上农历、节气和节日，发过文的日子用淡紫底标出来，
翻月和回到今天都能点。卡片底色同样压成实底，不然被背景图透上来也是糊的。

按之前说的，不做日程、不做记事——点日期什么都不发生，就是个能看清的日历。

### 标签砍到 7 个，每页 12 篇

标签攒到 30 个，其中 21 个只用过一次，点进去永远只有一篇文章，等于白挂。按同义合并：随笔、
书评、前端、摘录、情感、英文、影评。专名标签（作者名、书名、歌名）全删——它们不是分类，
是关键词，放正文里就够了。

每页篇数原来是 5，17 篇被切成 4 页，翻起来零碎。改成 12 篇，两页翻完，涨到 30 篇也才 3 页。

改的时候还发现分页函数里有个 `params0` 从来没定义过，一执行就抛错，被外层 try 吞了没人发现。
改成直接读当前 URL 参数。

### 七篇旧文章重写

最早那几篇读起来太像范文：每段结尾必升华一句，小标题三段等长，全是抽象道理，还编了些自己
根本没有的经历。这次全删了，只留能确定的东西——自己折腾这个站的过程，和几件普通的日常。

写的时候定了三条：不要对偶金句，段落结尾不总结，至少留一两个"蠢"的细节。真实感都在那些地
方，比如「其实我拿的是常温的，也没好意思说」。

### 欢迎页的规则改了三回

第一版做成永久只显示一次，写进了 localStorage，结果刷新也看不到，自己把自己关门外了。
第二版改成每次加载都判断，但条件写死成"当前页是首页"，停在别的页面刷新就不出现。
现在是：**每次打开或刷新都会出现一次，站内切换页面不弹**。不做持久化，刷新即重置。

### 部署

Cloudflare Pages 监听的是 `Reze520-website` 分支，不是 `main`。只推 main 会以为"改了没反应"。
现在仓库里配了双推，`git push` 一次两个分支都更新；或者直接 `bash deploy/deploy.sh "这次改了什么"`。

另外静态资源改了必须推一下 `?v=` 后面的版本号，否则浏览器缓存的还是旧文件，改了也白改。
