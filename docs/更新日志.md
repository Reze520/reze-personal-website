## 2026.10

### 「返回」掉回全部文章：页码把来源页覆盖了

- 现象：在技术栏点开一篇，看完点返回，直接退回「全部」。本地复现不出来，线上才有 —— 本地只放了几篇，列表凑不满一页，压根没有分页按钮；线上有六十多篇，每页十二篇，一到第二页问题就出来了。
- 根因是键名撞了。记来源的那个对象里，`p` 表示「这次是从哪个页面来的」（`home` / `writing`），而底部页码也用 `p` 写进去，值是数字 `0`。`saveListSource` 里对 `extra` 是无脑 `for in` 复制，数字 `0` 于是把 `"writing"` 覆盖掉了，读回来时 `readListSource` 认为这不是列表页，返回按钮只好退回默认的「全部文章」。本地没有分页按钮，`extra` 里就没有这个键，所以怎么点都正常 —— 这个差异把排查方向带偏了好一阵。
- 改法：页码改叫 `pn`，并且 `saveListSource` 里显式跳过 `p`，来源页只由第一个参数决定，不让别的键有机会改它。
- 第二处：从列表进文章时，`applyRoute` 的兜底还会再跑一遍 `markListSource`，用空的 `cat` / `tag` 把刚记下的分类冲掉。现在只在已经有 `home` / `writing` 来源时补一个 `id`，其余字段原样留着。

### 写作页刷新后掉回全部

- 返回其实是对的（回到「技术」），但只要 F5 一下，分类就没了。查下来是 `goPage` 在进入非首页页面时会把 `location.search` 清空 —— 那条规则本来是为了防止首页的分类被带进写作页，把筛选按钮全筛没。可写作页自己是带着 `?cat=技术` 进来的时候也被清了：页面看着还停在技术栏，地址已经变成 `#/writing`，刷新自然复位。
- 现在 `home` 和 `writing` 两个页面保留 `location.search`，只有切到别处才清；`applyRoute` 在没有 hash 参数时，会把地址里的 `?cat=` / `?tag=` 补进 hash，地址栏和页面状态始终一致。
- 顺带修了文件名：站点根路径下 `location.pathname` 是 `/`，`split("/").pop()` 得到空串，拼出来的 `/#/home` 在刷新时会落到别的文件上。首页 / 写作页的分类按钮现在直接写死 `index.html` / `writing.html`；跨页跳转时也把地址栏文件名同步过去。

## 2026.04

### 宿舍那段削掉了细节

- 上一版把宿舍写成「五楼、六人间、我睡上铺、对面下铺」，太具体了，具体到不像回忆，像在填表。人回忆一间宿舍，不会记得自己睡第几张床的编号，只记得进去的那股潮味和窗外能看见什么。
- 现在只留「一楼」，剩下的是环境：进门有股潮味、箱子轮子在水泥地上响、窗外只有对面楼的墙根和一丛草。楼层本身还留着，因为它决定了窗外能看见什么——五楼能看对面楼一排窗户，一楼只能看墙根，这个差别是真实的。
- 顺带把「阳台」「我们四个人」这类数得清的地方也软掉了，写成「宿舍楼门口」「宿舍里」。

### 把《第一次在武汉下车》改成大学那一版

- 原来那篇是按「搬到武汉」写的：七楼的房间、上班过江、一个人住。写的时候我只记得「2023 年到武汉」，口径猜错了一层——实际上是去武汉上大学，不是搬家。
- 改的不是几个词，是整条线：改成九月初开学报到、我爸送我到校门口；宿舍五楼六人间，我睡上铺；第一次去江边改成军训晚上跟舍友一起出门；「上班过江」换成那年冬天实习；「住了几年」换成「读四年书」。加了一节「过早」，写大学四年在楼下那条街吃早饭的事，这个城市真正留在身上的其实是这些。
- 结尾落点也改了：四年之后我走了，江还在那里。原来那句「把我跟这个城市连在了一起」留着，因为不管住还是读书，那个感觉是一样的。

### 两篇武汉；顺手把「返回」这件事修了

- 新增《第一次在武汉下车》，写的是我刚到武汉那阵子：出站那股湿热、七楼朝西的房间、第一次一个人摸到江滩、夏天四十度的作息被改、冬天江上的雾。都是些具体的小事，写它是因为回头看，真正把我跟这座城市连起来的不是哪件大事，是「哪条路能绕过去不用等红灯」这种。
- 新增《江月年年望相似》，起因是站在江边想起「人生代代无穷已，江月年年望相似」。高中背它只想着默写，那天才明白它问的就是自己。文里把《春江花月夜》中间那几段原文整块引了一遍。
- 两篇时间定在 2023 年，前后隔一个多月，正好是刚搬过去那半年。

### 返回时不再跳回首页

- 之前从「生活」这一类点进文章，点返回会落到首页，因为返回按钮写死了 `writing.html`，而 `applyRoute` 在没有 hash 的时候一律回首页。现在点进文章时会记下来源（哪个页面、哪个分类、当时的滚动位置），返回按钮直接回到那一栏，连滚动位置一起还回去。
- 分类切页时也把分类写进地址（`writing.html?cat=生活`），刷新之后还停在原地。

### 返回这件事，首页那一半一直没修好

上一轮说修好了，其实只修好了写作页那一半。首页点「生活」再进文章，返回还是回文章列表，而且选中的是「全部」。这轮把它掰开了：

- 根因是 `index.html` 的 `.app` 上根本没有 `data-page` 属性（只有各个子页面自己在 HTML 里写了），而记来源的第一步就是读这个属性。读不到就直接 `return`，也就是说「首页 → 文章」这一步压根没记来源；等到了文章页，又走文章页那个兜底分支，把来源当成 `writing` 记了下来。所以返回永远回文章列表。
- 改成不只看 `data-page`：读不到就从 hash 里解析当前页。顺手把「全部」这个伪分类挡掉——它不是真分类，不该往地址里写。
- 写作页那个分类按钮其实一直没渲染出来过：`renderMain` 只有「文章页 / 其它」两路，`writing` 落进了 else，渲染的是首页那套帖子区块。所以 `#g-filters .g-chip` 一直是 0 个，`writingMainHtml()` 里的分类 chips 写了却从没被调用——死代码。现在给 `writing` 单开一路。
- 还有个连带问题：首页点分类会把 `?cat=生活` 写到地址栏，然后点导航去写作页，这个 `?cat` 被一起带过去了。写作页按 `location.search` 初始化，于是它的分类按钮全被筛成「不存在」，一个都不显示。现在切页时把列表页残留的 query 清掉，分类只从 hash 里读。
- 现在的实际结果是：首页点「生活」→ 进文章 → 返回，落在 `#/home?cat=生活`，「生活」亮着，3 篇，滚动位置也回得去；写作页点「技术」同理。直接打开带分类的地址、刷新一次，都还停在那一栏。

### 把 AI 排版拆了；补三篇日常主题

- 之前每篇都是八到十个小标题，每个小节两三段短句，一段四五十个字——那是模板的节奏，不是人写字的节奏。这回把所有文章的小标题从 379 个压到 245 个（撑不起来的小节直接并进上一节），同一节里的碎段合并成长短不一的段，平均段长从五十多字变成两百字左右。读起来终于像一段一段在说话，而不是一条一条在列点。
- 引用又补了八段。这次不加引用框，直接把话写进正文——「《送行》那篇最后一句我记得特别清楚：'你走，我不送你……'」，这样才像自己写文章时顺手引的，不是排版排出来的。

  - 《已读不回这件事》，从一条十一月没被回复的消息写起，写到回执这个功能本来是给工作设计的，落到人和人之间就变味了。
  - 《手机为什么越用越慢》，闪存写满、后台、系统升级、电池老化、应用变胖，五件事拆开讲，最后给了几个自己试过确实有用的办法。
- 三篇都没列点、没小结，段落长短不齐，按自己的说话习惯写。

### 小标题掉了第一个字；标题换了；引用加厚

- 一个藏了很久的 bug：`to_html` 里 `"## "` 明明只有 3 个字符，代码却按 `[4:]` 截，于是每个小标题都少掉头一个字——「上册」变「册」、「宋钢之死」变「钢之死」、「余华写时代」变「华写时代」。四十多篇的老文章全都这样，我自己一直没发现。改成 `[3:]`，重发了一遍。
- 文章标题之前几乎全是「《书名》：一句感想」这个模子，二十多篇一个句式，太像批量生成的。这次全部重写，改成参差的：有的只写一个场景（「高二在被窝里读完《活着》」），有的只写一句人话（「柴静后来不太敢下判断了」），有的干脆把书名放前面（「《兄弟》上册我折了个角」）。同一个句式不再连着出现。
- 引用原来每篇只有开头一段，太薄。这次又补了 21 段：书里那些我确实记得住的段落，放到对应那一节的标题底下当题引（《我与地坛》的车辙、《万历十五年》那句「以道德代替法制」、《边城》的开篇指路）；技术文配上了论文和官方文档的原文（Transformer 那句、Raft 那句、RFC 8446、Rust 官方书第四章）。现在 31 篇有引用，一共 45 段。
- 毛玻璃调淡了：模糊从 22px 降到 11px，底色从 0.56 降到 0.48，背景画能透出来一点，字还是压得住。悬停也跟着降到 0.62。

### 配图不再被裁、卡片改回磨砂，正文里加了原文引用

- 上一次给文章配图时，我给 `figure` 起的 class 叫 `cover` / `wide`，结果正好撞上全站通用的 `.cover`（卡片缩略图那套：`aspect-ratio: 16/10` + `overflow: hidden` + `object-fit: cover`）。所以封面进去就被裁成一条，只剩中间一块。改名叫 `pg-cover` / `pg-wide`，另外在 `figure.pg-fig` 上把 `aspect-ratio`、`overflow`、`background` 都显式复位了一遍，以后就算再有同名 class 也不会被误伤。
- 卡片背景之前为了「让原图透出轮廓」把模糊整个关了，底色又是 0.66 的半透明深蓝，背景一换成亮色插画，卡片上的小字就浮在画上。这回把 `backdrop-filter: blur(22px)` 加回来，底色压到 0.56，悬停时改成「变实」（0.74 的深蓝）而不是像原来那样变透明（`rgba(255,255,255,0.08)`）——那条悬停规则是照浅色主题抄的，放到深色卡上正好反了。
- 正文新增两种块：`> ` 开头的原文引用（左侧竖线 + 一对淡淡的引号，出处靠右），以及文末的「参考与延伸」列表。书评影评各挑了一句话放进去，比如《活着》用的是余华自序那句、《边城》用的是结尾那句；文末挂豆瓣条目和长评、B 站和知乎的搜索入口，技术文挂官方文档和论文。
- `build_books.py` 相应支持引用块、无序列表和 `[文字](链接)`，顺手把 `<figure>` 被包在 `<p>` 里的老问题一起改了（块级元素塞进段落，浏览器会自己拆开，位置容易乱）。

### 把攒了小半年的读书笔记整理出来了

二十四篇，一本一篇，断断续续写了小半年，多数是晚上或者通勤路上记的。一开始没想写这么多，就是读完一本随手记几句，攒着攒着就成了一摞。

整理的时候按读完的先后排，最近的搁最前头，没刻意排别的顺序。每篇都从自己怎么碰上这本书写起，中间挑几段记得住的聊，结尾不总结，写到哪算哪。翻回去看，发现好多篇开头都是「这本书我是……」，有点重复，犹豫了一下还是没改——写字的人总有点自己的口头禅，改了反而不像自己了。

## 2025.06

### 二十四篇书评，全部重写了一遍

原来的书评太短，七百到一千三百字，读完像说了个开头就没了。这次一本一本重写，先讲自己怎么读到这本书、当时是什么状态，再挑三到六个点细说——人物、结构、原文里戳到我的句子、自己的对照、还有那本书所处的时代。

## 2023.05

### 天气页，和那个把我坑惨的输入法

加了个天气页，数据用 Open-Meteo——免费、不用申请 key、前端能直接请求，省事。默认放北京、上海、杭州，想加别的城市搜一下就行，最多八个，点上面的城市条就能换。温度、体感、湿度、风、降水、紫外线、气压、日出日落都有，还能看未来 24 小时和一周。

最坑的是搜索框。一开始搜完就把整个区域重绘一遍，连输入框都删了重建，结果打拼音打到一半框没了，拼音永远变不成汉字，只剩一串 `shi'yan` 这种残渣。后来改成只刷新下面的结果列表、不碰输入框，再监听输入法的开始和结束事件，组合输入的时候先别搜。折腾了半天。

（香港、澳门、台湾按中国行政区划标注。）

### 导航页扩到一百五十多个站

原来存了五十来个常用站，干脆一次补全，凑到一百五十多个，分成十四类。

每一个我都在没有代理的网络下点开试过。判断标准很土：能连上、能返回东西就算通，403、401 也算——很多站本来就不欢迎脚本。这么试下来，ChatGPT、YouTube、维基这些打不开的删了十个，免得点进去一片白。

图标也从在线服务换成本地缓存，整站图标加一起不到一兆，打开快，也不怕哪天图标服务挂了。图标原来用了懒加载，结果滚动快了有些图根本不加载，页面留一排空方块，后来改成先显示站名第一个字、加载完再淡入。还有个别站点的图标格式解不开，用 PIL 转了一道。

### 播放器：曲目列表和三种播放模式

加了曲目列表，能点着切歌，也能上一首下一首。播放模式做成顺序、单曲、随机三个轮着换，选过哪个下次还记得。歌词默认收起来了，想看的再点开。

顺手修了个角标显示错乱的毛病：单曲循环那个小「1」原来挂在按钮的伪元素上，跟悬浮提示抢同一个位置，鼠标一放上去就变成一个装着「1」的黑方块。改成按钮里单独放个元素控制显隐才正常。

### 进度条终于能拖了

这事折腾了我一晚上。一开始以为是音频文件的问题，换了几个格式都不行。

后来才发现跟文件没关系：托管那边返回静态资源时没带 `Accept-Ranges`，拖进度条发的分段请求，它一律回整个文件，浏览器就定不了位。连 CSS、图片都是这样。

最后把音频单独挪到一个支持分段请求的 CDN 上，页面还在原来的地方，地址前缀收在一处，以后换也方便。副作用是 CDN 有缓存，新加的音频得等它同步一会儿。

### 欢迎页改成一直待在顶上

之前欢迎页只在第一次进站时出现，看完就没了，想再看一眼还得刷新。现在它就在页面最上面，随便翻到哪，往上滚都能回去。

切页面的时候会自动落到正文开头，免得每次都先划过大屏。刷新和直接点文章链接的落点分开处理，不然打开一篇文还得先看欢迎页。滚动位置的计算还做了点处理，同一个页面不会来回滚两次。

### 日历挪进右栏，独立页面删了

原来单独一个日历页，进去的人没几个，干脆删掉，旧链接指回首页。右栏这个小日历顺手补了农历、节气和节日，发过文章的日子会标出来，能翻月份，也能一键回到这个月。

日程和记事没做——试过，自己用不上，还占地方，就砍了。

### 标签砍到七个，列表一页十二篇

之前标签三十个，好多是只出现一次的专名，筛出来就一篇文章，没什么意义。狠狠心砍到七个：随笔、书评、前端、摘录、情感、英文、影评。

一页五篇太少，翻页翻得烦，改成十二篇。改的时候还撞了个报错，筛选函数引用了一个没定义的变量，列表一打开就崩，被外层的 try 吞了，找了一会儿才找到。

### 导航和时间线不再一拉到底

导航页加了顶部分类筛选，点一个分类就只看这一类；「全部」里每类只露三个，想看全的点「全部 N 个」。时间线先只显示最近十条，底下有个「加载更早」，一次再拉十条，用完按钮自己消失。

也想过用分页，但这个版式下分页既不好看，窄屏上更别扭，还是一点点展开自然。

### 版本过期提醒

标签页开太久，浏览器不会重新拉 JS，改完看着像没生效。现在切回页面时对一下版本号，跟当前加载的不一致，就在底部弹一句「站点已更新，点这里刷新」。

### 把几篇文章和动态重写了一遍

七篇文章、四条动态，回头看全是模板味：段落结尾爱下结论，句子爱对仗，情节还有编的。一篇一篇删了重写，尽量写成自己会说的话。正文同步到了云端，旧链接没动。

## 2020.07

### 站点基础

没用框架，也没引依赖，HTML、CSS、JS 全是手写的，整站静态。图的就是简单、国内打开也快。

三栏的骨架：左边个人信息，中间正文，右边动态和日历。首页、文章、关于都用这一套。切页面改成单页路由，只换内容区，播放器不重建，背景音乐能一直放。顶栏三段式居中，图标配文字，用得不多的入口收进「更多」里。

配色从黑白极简换成了一套偏紫的冷色，暗色模式一起做了。搜索（Ctrl+K）和打开站点那屏欢迎页，也是这天弄的。

### 内容与功能

光有文章太单薄，又添了动态、相册、网址导航三种。时间线只记站点本身改了什么，不跟文章混在一起，翻起来清楚。

文章页右边加了个目录，从正文小标题自动生成，点一下跳过去，滚到哪一节哪一行就亮起来。背景音乐和 LRC 歌词也接上了，点开能看，播到哪句哪句亮。播放器做成了唱片机的样子，歌词能分栏内、悬浮、底部三种方式看。

### 部署

Cloudflare Pages 的生产分支是 `Reze520-website`，推 `main` 不触发构建，所以仓库里配了双推，一次 `git push` 两个分支一起更新。

静态资源改了记得把 `?v=` 的版本号往前推一格，不然浏览器还读旧缓存。
